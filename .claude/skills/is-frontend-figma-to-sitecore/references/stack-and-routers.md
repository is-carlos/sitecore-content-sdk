# Stack detection and router differences

This skill targets the Sitecore **Content SDK** (`@sitecore-content-sdk/nextjs`, 2.x) on Next.js 16. It never generates JSS code (`@sitecore-jss/*`).

## Detect

| Question | How to tell |
|---|---|
| SDK | `package.json` deps. `@sitecore-content-sdk/nextjs` → continue and note its version. Only `@sitecore-jss/*` → **stop** (see SKILL.md Step 2). Both (mid-migration) → Content SDK APIs only, and say so. |
| Router | `src/app/` (or `app/`) with a `page.tsx` under it → **App Router**. `src/pages/[[...path]].tsx` → **Pages Router**. |
| Component root | `componentMap.paths` in `sitecore.cli.config.ts` (usually `src/components`). |
| Component map exclusions | `componentMap.exclude` in `sitecore.cli.config.ts`. |
| Styles root | `src/styles/` — the token layer's folder (`main.scss`, `abstracts/`, `tokens/`, `base/`). If the project already keeps global styles somewhere else, report it and ask whether to move them into `src/styles/` or leave them. |
| Token layer | Which partials in `src/styles/tokens/` and `src/styles/abstracts/` exist and have content. Report them as "tokens: color, type…". None → suggest `init`. |
| Global stylesheet import | Pages Router: `src/pages/_app.tsx`. App Router: the root `layout.tsx`. Note whether `src/styles/main.scss` is already imported. |
| `sass` | In `devDependencies`. Required. Missing → ask to install it (`npm install -D sass`). |
| CSS modules convention | Existing `*.module.scss` names next to components (`<Name>.module.scss` or `<Name>.styles.module.scss`). Follow what exists; default `<Name>.module.scss`. |
| Fonts | `next/font` usage (e.g. `src/lib/fonts.ts`) and the CSS custom properties it exposes (`--font-*`). |
| Storybook | `.storybook/`. Note the framework (`@storybook/nextjs` or `@storybook/nextjs-vite`), whether `preview.tsx` imports the global stylesheet, and whether a decorator wraps stories in `SitecoreProvider` (e.g. `.storybook/sitecore.tsx`). |
| Showcase pages | `src/pages/showcase/` or `src/app/showcase/`, and whether `proxy.ts`'s matcher excludes `showcase`. |
| Proxy | `src/proxy.ts` (or `proxy.ts`): its `config.matcher`. |
| Local sample content | `mock-data/` plus a `dev:mock` script (a project-specific local GraphQL mock). Report only. |
| Conventions | `AGENTS.md`, `CLAUDE.md`, `CONVENTIONS.md`, `Skills.md`, `.agents/skills/`, `.cursor/rules/`. Read them; their rules override this skill. When the official Content SDK skills ship in `.agents/skills/`, read `content-sdk-component-scaffold`, `content-sdk-field-usage-image-link-text` and `content-sdk-editing-safe-rendering` before the component mode. |
| Serialization | `sitecore.json` / `*.module.json`. Report only: this skill does not write Sitecore items. |

## Router differences

Everything else in this skill — fields, CSS modules, tokens, stories, Figma extraction — is the same for both routers.

| Concern | Pages Router | App Router |
|---|---|---|
| Component kind | Every component is a React component hydrated on the client. | Server component by default. Add `'use client'` only to the smallest part that needs state, effects or events. |
| Editing state | `const { page } = useSitecore(); page.mode.isEditing` | Server: `props.page.mode.isEditing` (`page` is passed down by the placeholder). Client: `useSitecore()`. |
| Missing datasource | Follow existing components: `withDatasourceCheck()<Props>(Component)` from the SDK, or a `rendering.dataSource` check. | Check `props.rendering.dataSource` by hand. `withDatasourceCheck` is a client component (it calls `useSitecore()`), so wrapping a server component with it turns it into a client one. |
| Child placeholders | `<Placeholder name="…" rendering={rendering} />` | `<AppPlaceholder name="…" rendering={rendering} page={page} componentMap={componentMap} />`. Client components use the client component map (`.sitecore/component-map.client.ts`). |
| Data beyond the layout | `getComponentServerProps` / `getComponentStaticProps` exported from the component. | Fetch inside the server component. |
| Global stylesheet import | `import '../styles/main.scss';` at the top of `src/pages/_app.tsx`. | The same import in the root `layout.tsx` (relative path from its folder, e.g. `../styles/main.scss` from `src/app/`). |
| Showcase page | `src/pages/showcase/<kebab-name>.tsx` + `src/pages/showcase/index.tsx`. | `src/app/showcase/<kebab-name>/page.tsx` + `src/app/showcase/page.tsx`. |
| Component map | One map (`.sitecore/component-map.ts`). | Server map plus client map; the generator puts `'use client'` components in `component-map.client.ts`. |

Never hand-edit `.sitecore/component-map*.ts`; it is regenerated by `npm run dev` (watch), `npm run build`, or `npm run sitecore-tools:generate-map`.

## Checks

- `npm run lint`, `npx tsc --noEmit`.
- `npm run build` first runs `sitecore-tools project build`, which needs Sitecore credentials (or the local mock running). Don't run it unless the user asks, and never into the `.next` folder of a running dev server (`NEXTJS_DIST_DIR=.next-build` when `next.config.js` supports it).
